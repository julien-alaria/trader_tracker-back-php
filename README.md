# Trader Tracker - PHP Backend

## Rewriting the Node.js/Express backend of the Trader Tracker project in **native PHP**. 

It uses the same database, routes, and business logic—only the language changes. The frontend (vanilla JS) requires no modifications to work with this backend, except for a single line of configuration (see below).

## Prerequisites

- **PHP 8.2 or higher**
- **Composer**
- **MySQL 8.0 or MariaDB (11.x tested)**
- **Optional: Docker + Docker Compose (to run everything without installing MySQL locally)**

## Installation

```bash
git clone https://github.com/julien-alaria/trader_tracker-back-php.git
cd trader_tracker-back-php
composer install
```

`composer install` generates the `vendor/` directory from `composer.lock` (which is never version-controlled and is regenerated during each installation).

## Configuration

Create a `.env` file at the project root:

```dotenv
DB_HOST=127.0.0.1
DB_PORT=3306
DB_USER=your_user_name
DB_PASSWORD=your_db_password
DB_DATABASE=trader_tracker
JWT_SECRET=change_this_secret_in_production
APP_PORT=8000
```

## Database

### Option A — Local MySQL/MariaDB

```bash
mysql -u root -p trader_tracker < docker/mysql/init/01-schema.sql
mysql -u root -p trader_tracker < docker/mysql/init/02-seed.sql
```

### Option B — Docker (standalone database, isolated from the rest of the system)

```bash
docker compose up -d db
```

The schema and test dataset load automatically when the container starts for the first time, using files from `docker/mysql/init/`.

## Starting the server

**Locally (recommended for development)**:
```bash
php -S localhost:8000 -t public
```

**With Docker (backend + database, isolated environment)**:
```bash
docker compose up --build
```

The server listens on `http://localhost:8000`.

## Connecting the frontend

By default, the frontend points to the Node backend (`http://localhost:3000`). To point it to this PHP backend, modify a single line in `front/src/config/api.js`:

```javascript
export const API_BASE_URL = "http://localhost:8000"
```

**CORS**: `public/index.php` explicitly allows the origin `http://127.0.0.1:5501` (the default port for the VS Code Live Server extension). If the frontend is served from a different URL (different port, `localhost` instead of `127.0.0.1`, etc.), update the following line in `public/index.php` with the exact URL:
```php
header("Access-Control-Allow-Origin: http://127.0.0.1:5501");
```
CORS matching is strict and case-sensitive.

## Project Structure

```
public/
index.php          → single entry point (bootstrap: autoload, .env, CORS, routing)
src/
routes.php         → API route declarations
Router.php         → custom routing engine (dynamic parameters, middleware chain)
Database.php        → PDO connection (singleton)
Controllers/        → HTTP logic (request → response)
Models/              → SQL queries
Middlewares/         → Auth, role verification, file upload, asset verification
Services/             → StockService (reading static market data)
Utils/                 → validation, sanitization, error handling, request parsing
data/                   → JSON files (nasdaq.json, forex.json, commodities.json)
docker/
mysql/init/             → SQL schema and seed data
```

## Notable Architectural Points

- **Custom routing** with dynamic parameters (`:id`) using regular expressions and a middleware chain (inspired by the Express pattern, adapted for native PHP).
- **File upload**: PHP does not natively parse `$_FILES`/`$_POST` for multipart `PUT`/`PATCH`/`DELETE` requests—a manual parser (`MultipartParser`) bypasses this limitation for profile updates involving photos.
- **Authentication**: JWT (`firebase/php-jwt`), passwords hashed using `password_hash()` (bcrypt, compatible with hashes generated by the original Node project). - **Security**: PDO prepared statements used throughout, role enforcement via `AuthMiddleware::forRoles()`, and analyst specialization verification via `SpecializationMiddleware`.

## Testing

No automated testing framework is currently in place; each route was manually validated (using Postman and a browser) during development. Potential area for improvement: adding PHPUnit to cover validators and sanitization logic.
